# 2026-11-11 从 GitHub 干净克隆到能建图

在一台刚清掉 LIGO / rslidar 的 Ubuntu 20.04 笔记本上，HTTPS 克隆 `CharlesTsoi/M20_Charles`（当时 `023bdbd`），编到桌面图标能开、室内能建图。下面是这次踩到的点，以及已经写回仓库的改动。

## 克隆和编译

- SSH `git@github.com` 会被对端直接关掉。用 HTTPS。
- `./build.sh` 只编雷达驱动。LIGO、Ceres、`gtsam` 都不在仓库里。
- 公开版 LIGO 是 [Joanna-HE/LIGO](https://github.com/Joanna-HE/LIGO)，还要 `gnss_comm`、`livox_ros_driver`。Ubuntu 20.04 的 apt Ceres 是 1.14，LIGO 的 CMake 要求 2.1，要从源码编到 `/usr/local`。
- 公开源码**不读** `/etc/nav_ligo/licensefile/license.dat`。那是部分 Orin 镜像里授权二进制的检查。

手把手（不需要 Grok）以仓库根目录 `README.md` 为准。

已经加上 `scripts/build_ligo.sh`。干净机器：

```bash
git clone https://github.com/CharlesTsoi/M20_Charles.git
cd M20_Charles
./build.sh
./scripts/build_ligo.sh
./m20.sh desktop
```

## 网络

狗网卡必须是 `10.21.31.100/24`、`never-default`、没有网关，组播 /32 走这块卡。

NetworkManager 插上 USB 网卡后会自动生成「Wired connection 1」，带上 `10.21.31.1`，metric 比 WiFi 还小。这时 `ip route` 的 default 在狗网段上，访问 GitHub 变成 `gnutls_handshake() failed`。删掉那份自动连接，按 README 建 `m20-lidar`。

## 桌面图标

`./m20.sh desktop` 以前写出 `Path="/home/用户"`。GNOME 不认带引号的 Path，双击没反应，`desktop-file-validate` 会报不是绝对路径。Python 窗口本身是好的。

现在改成不带引号的 `Path=`，用 `ligo_mapping/online/launch_gui.sh` 启动（不经过 fishros 的 `~/.bashrc`），并写一份 `~/.local/share/applications/m20-indoor-mapping.desktop`。第一次若提示未信任，右键允许启动。日志在 `~/ligo_sessions/gui_desktop.log`。

## 界面停在加载

雷达已经在发大约 10 Hz 的点云，界面仍报「ROS1 上没有 `/rslidar_points`」。

1. rospy 默认订阅缓冲区 64 KB，一帧 Airy 大约 2 MB。`wait_for_message` 永远收不完。探测改成 32 MB 缓冲区。
2. 再点一次「开始」会再起 `ros1_pub`，旧节点被同名挤掉，15731 报 `Address already in use`。开始前先清残留桥接进程，并等到 15731 在听再起 `ros2_feed`。

## 机体裁剪

这次室内 `ros1_pub.log` 里 `body-crop` 到过 63%。盒子偏大，近处墙会被一起删。地图发糊或贴着狗缺一块时，改 `ros1_pub.py` 的 `body_half_x` / `body_half_y`，见 [`ligo_mapping/gui/vibration.md`](../ligo_mapping/gui/vibration.md)。
